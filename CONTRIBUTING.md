# Внесение изменений

Регистрируйте проблему с ожидаемым и фактическим поведением. Для ошибок авторизации не включайте токены, коды входа, персональные данные или внутренние адреса.

Код ядра разделён по ответственности: `identity`, `session`, `vault`, `postgres`, `proxy`, `oauthbridge`, `mcpserver`, `modelaccess`, `webui`. Новый клиент подключается по стандартному MCP/OAuth; не добавляйте зависимость ядра от внутреннего формата сессий чата.

Для исправления ошибки добавьте регрессионный тест. Изменения сессий проверяйте с PostgreSQL, включая конкурентные запросы. Для нового IdP нужен тест discovery, проверки access token, refresh и обработки отказа; одной совместимой формы claims недостаточно.

Перед предложением изменения выполните `make test`, `make build`, `make helm` и `go vet ./...`. Не оставляйте необъяснённые пропуски интеграционных тестов. Комментарии в коде пишутся по-английски, эксплуатационная документация — по-русски.

Изменения API, БД и поведения выхода должны сопровождаться инструкцией обновления и отката. Не добавляйте рабочие секреты, заполненные локальные конфигурации и зависимости без lock-файлов.
