# Проверка реализации и установки

## Локальные проверки

```sh
go test -race ./...
go vet ./...
make build
helm lint deploy/chart
```

Для тестов PostgreSQL задать `PORTICO_TEST_DATABASE_URL` на отдельную локальную тестовую БД `portico_test` на `127.0.0.1` или `localhost` (произвольный порт). Эти параметры соответствуют проверке безопасности интеграционного теста политик и конфигурации CI. В отчёте о проверке указывать, запускались ли они: результат с пропусками не является полной проверкой сессий и конкурентного доступа.

В коде имеются тесты OIDC, шифрования, сессий, PKCE, refresh, фильтрации инструментов, политик моделей, потоковых ответов и HTML. Наличие теста не означает, что он запускался для каждого опубликованного образа. Версию, команды и результат фиксировать для конкретного выпуска.

## Приёмка установки

1. Проверить DNS, HTTPS, discovery и сетевые разрешения.
2. Без credentials получить отказ MCP и API моделей.
3. Войти пользователем разрешённой группы; получить только назначенные модели и обычный ответ.
4. Пользователем без группы проверить пустой каталог и запрет прямого запроса запрещённой модели.
5. Пройти отдельный MCP-вход, получить список инструментов и выполнить операцию чтения.
6. Проверить права второго пользователя на чужие объекты в целевом API.
7. Проверить обновление токенов, logout, истечение и повторный вход.
8. Проверить работу через разные реплики и после замены одной реплики.
9. Только после проверки авторизации запускать разрешённую задачу анализа и проверять её жизненный цикл отдельно.

Локальные тесты не подтверждают сквозную совместимость конкретной установки с IdP и клиентами. Проверку полного цикла, независимый аудит безопасности и нагрузочное тестирование необходимо проводить отдельно.
