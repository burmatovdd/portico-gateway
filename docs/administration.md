# Управление доступом к моделям

Административный интерфейс доступен по `https://<portico-host>/admin/`. Администратор Portico может войти с локальным именем и паролем. OIDC-вход настраивается отдельно и требует точного совпадения группы из подписанного токена с `config.admin.groups`. Статус администратора в приложении чата сам по себе такого права не предоставляет.

## Подготовка

1. Выбрать хотя бы один способ входа: локальный аккаунт (`config.admin.local.enabled`) или OIDC-группу (`config.admin.groups`). Для локального входа задать `config.admin.local.username` и сохранить хеш пароля в ключе `local-admin-password-hash` существующего Kubernetes Secret `existingSecret`. Пароль по умолчанию отсутствует. Сам пароль не добавлять в values, манифесты или переменные окружения.
2. Для OIDC-входа создать административную группу у провайдера, назначить сотрудников, добавить разрешённый redirect URI `https://<portico-host>/admin/callback` и указать точные идентификаторы групп в `config.admin.groups`. При локальном входе эти действия не требуются.
3. Включить `config.admin.enabled` и указать `config.admin.catalog_url` — базовый URL OpenAI-совместимого API LiteLLM с окончанием `/v1`.
4. Включить `models.enabled` и `models.config.policy_store: postgres`. Обоим компонентам требуется доступ к одной БД Portico. Компоненту core также требуется доступ к LiteLLM и существующему секрету `litellm-api-key`.
5. Применить обновление Helm. Дальнейшие изменения правил через интерфейс перезапуска не требуют.

Публичный адрес определяется конфигурацией; домен и организация не заданы в коде.

Для создания хеша в корне исходного кода используйте `go run ./cmd/portico-admin-hash`. Программа читает пароль из stdin, требует не менее 16 байт и печатает только соль и PBKDF2-SHA256-хеш. На терминале с Bash можно ввести пароль без отображения:

```bash
read -rs -p 'Пароль администратора Portico: ' PORTICO_ADMIN_PASSWORD; printf '\n'
printf '%s\n' "$PORTICO_ADMIN_PASSWORD" | go run ./cmd/portico-admin-hash
unset PORTICO_ADMIN_PASSWORD
```

Вывод запишите через используемый менеджер секретов в `existingSecret` как `local-admin-password-hash`. После обновления секрета перезапустите только core-поды Portico, чтобы они прочитали новый хеш; прежние локальные сеансы после смены хеша станут недействительными. Не передавайте сам пароль в командной строке или переписке. На странице `/admin/login` отображается локальная форма; при настроенной группе также появляется отдельная ссылка для OIDC. Локальный аккаунт может управлять только административной страницей Portico и не получает пользовательские OAuth/MCP-права.

## Редактирование

В строке правила указываются точный идентификатор группы из токена и идентификаторы моделей из LiteLLM. Например, `organization/analysts` и `triage, pentest`. Каталог показывает модели, возвращённые LiteLLM с серверным ключом Portico. Для удаления правила следует очистить оба поля строки. Полностью пустой набор правил отзывает все пользовательские разрешения на модели.

Группы вводятся по их идентификаторам: текущий интерфейс не запрашивает административный каталог пользователей и групп Casdoor. Новую модель сначала необходимо разрешить серверному ключу Portico в LiteLLM. Интерфейс Portico распределяет этот доступ между группами и не изменяет ключи LiteLLM.

Сохранение атомарно обновляет правила и журнал изменений. Журнал содержит субъект и издателя удостоверения, время, прежние и новые правила. Интерфейс показывает последние 50 изменений. Конфликт версии при одновременном редактировании возвращает актуальные правила; молчаливой перезаписи нет.

## Применение и отказоустойчивость

Компонент models читает правила из общей БД перед каждым новым запросом, включая получение списка моделей. При недоступной БД запрос отклоняется с `policy_unavailable`: перехода к старым разрешениям нет. `/readyz` проверяет доступность правил, `/healthz` остаётся проверкой процесса.

Правила `models.config.rules` заполняют БД только при первом запуске. Последующие обновления Helm и рестарты не перезаписывают сохранённые права. Возврат к статическому режиму требует отключения админки и отдельного осознанного изменения конфигурации; Helm отклоняет сочетание активной админки со статическими правилами.

Уже принятый поток ответа не прерывается при изменении правила. Изменения членства в группах удостоверяющего провайдера видны после обновления или повторного получения токена; срок жизни токена определяет возможную задержку. Пользовательский интерфейс чата также может кэшировать список моделей — после изменения прав следует обновить его список или страницу.

## Защита

OIDC-вход использует PKCE, nonce и одноразовое состояние с ограниченным сроком действия. Токены провайдера хранятся на сервере в зашифрованном виде. Локальный вход проверяет соль и хеш пароля, ограничивает вход после пяти неудачных попыток на 15 минут и создаёт отдельную отзывную сессию в БД. Браузер получает защищённую HttpOnly-cookie. Изменения требуют действующей административной сессии, проверки Origin и CSRF. Редактирование локального пароля и списка административных групп через эту страницу не предоставляется.
