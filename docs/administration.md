# Управление доступом к моделям

Административный интерфейс доступен по `/admin/`. Вход выполняется через настроенный OIDC-провайдер. Право администрирования определяется точным совпадением группы из подписанного токена с `config.admin.groups`. Статус администратора в приложении чата сам по себе такого права не предоставляет.

## Подготовка

1. Создать в провайдере идентификации отдельную административную группу и назначить ответственных сотрудников.
2. Добавить в приложение Portico разрешённый адрес возврата `https://<portico-host>/admin/callback`.
3. Включить `config.admin.enabled`, указать группы и `config.admin.catalog_url` — базовый URL OpenAI-совместимого API LiteLLM с окончанием `/v1`.
4. Включить `models.enabled` и `models.config.policy_store: postgres`. Обоим компонентам требуется доступ к одной БД Portico. Компоненту core также требуется доступ к LiteLLM и существующему секрету `litellm-api-key`.
5. Применить обновление Helm. Дальнейшие изменения правил через интерфейс перезапуска не требуют.

Публичный адрес определяется конфигурацией; домен и организация не заданы в коде.

## Редактирование

В строке правила указываются точный идентификатор группы из токена и идентификаторы моделей из LiteLLM. Например, `organization/analysts` и `triage, pentest`. Каталог показывает модели, возвращённые LiteLLM с серверным ключом Portico. Для удаления правила следует очистить оба поля строки. Полностью пустой набор правил отзывает все пользовательские разрешения на модели.

Группы вводятся по их идентификаторам: текущий интерфейс не запрашивает административный каталог пользователей и групп Casdoor. Новую модель сначала необходимо разрешить серверному ключу Portico в LiteLLM. Интерфейс Portico распределяет этот доступ между группами и не изменяет ключи LiteLLM.

Сохранение атомарно обновляет правила и журнал изменений. Журнал содержит субъект и издателя удостоверения, время, прежние и новые правила. Интерфейс показывает последние 50 изменений. Конфликт версии при одновременном редактировании возвращает актуальные правила; молчаливой перезаписи нет.

## Применение и отказоустойчивость

Компонент models читает правила из общей БД перед каждым новым запросом, включая получение списка моделей. При недоступной БД запрос отклоняется с `policy_unavailable`: перехода к старым разрешениям нет. `/readyz` проверяет доступность правил, `/healthz` остаётся проверкой процесса.

Правила `models.config.rules` заполняют БД только при первом запуске. Последующие обновления Helm и рестарты не перезаписывают сохранённые права. Возврат к статическому режиму требует отключения админки и отдельного осознанного изменения конфигурации; Helm отклоняет сочетание активной админки со статическими правилами.

Уже принятый поток ответа не прерывается при изменении правила. Изменения членства в группах удостоверяющего провайдера видны после обновления или повторного получения токена; срок жизни токена определяет возможную задержку. Пользовательский интерфейс чата также может кэшировать список моделей — после изменения прав следует обновить его список или страницу.

## Защита

Вход использует PKCE, nonce и одноразовое состояние с ограниченным сроком действия. Токены провайдера хранятся на сервере в зашифрованном виде. Браузер получает защищённую HttpOnly-cookie. Изменения требуют действующей административной сессии, проверки Origin и CSRF. Редактирование списка административных групп через эту страницу не предоставляется.
