# Доступ к моделям

Models — отдельный сервис Portico. Он принимает пользовательский JWT и предоставляет ограниченный OpenAI-совместимый интерфейс: каталог моделей и Chat Completions, включая потоковые ответы и function calling.

## Конфигурация

```yaml
models:
  enabled: true
  config:
    issuer: https://idp.example.org
    audience: chat-client-id
    organization: example
    groups_claim: groups
    upstream: https://litellm.example.org/v1
    allow_http: false
    max_request_bytes: 4194304
    max_duration_seconds: 600
    rules:
      example/red-team: [pentest]
      example/developers: [triage]
```

Это фрагмент values. Остальные настройки задаются по [инструкции установки](installation.md). Имена моделей должны точно соответствовать алиасам LiteLLM. `organization` проверяет подписанный claim `owner`; для IdP без этого claim оставить пустое значение и отдельно определить политику доверия к issuer и audience.

## Разделение прав

Пользователь получает объединение моделей разрешённых групп. Каталог без совпавшего правила пуст. Запрос к запрещённой модели возвращает 403; отсутствующий или неверный JWT — 401.

Один служебный ключ LiteLLM может разрешать несколько моделей. Portico ограничивает доступ пользователя подмножеством из политики. При добавлении модели необходимо обновить и политику Portico, и ограничения ключа LiteLLM. Ключ хранится в Secret и не передаётся клиентам.

Upstream фиксирован конфигурацией. Пользовательский JWT, cookies и произвольные входящие заголовки в LiteLLM не передаются. Запросы с подменой маршрута, повторяющимися JSON-полями или неподдерживаемыми параметрами отклоняются. Длительность потока ограничивается сроком JWT и `max_duration_seconds`.

## Клиенты и ограничения

Клиент должен передавать собственный access token IdP в Bearer-заголовке. Для Open WebUI используется `system_oauth`; инструкция приведена в [подключении клиентов](clients.md).

Models не выпускает OAuth credentials для произвольных CLI. MCP-авторизация OpenCode не даёт ему автоматически доступ к моделям. В конфигурации models задан один ожидаемый audience; подключение нескольких приложений с разными audience требует отдельного проектирования, а не добавления только группы.

Responses, embeddings и загрузка файлов не реализованы. Совместимость со всеми полями OpenAI API не заявляется. Readiness не проверяет доступность каждой модели или права реального пользователя.
