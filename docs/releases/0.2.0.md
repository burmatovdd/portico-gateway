# Portico 0.2.0 — подготовка обновления

Версия чарта: `0.3.0`.

Релиз добавляет административное управление доступом групп к моделям, отдельный пользовательский портал состояния проверок, скачивание опубликованных отчётов в Markdown, HTML и PDF и ограниченное восстановление после переполнения контекста.

## До обновления

- Дождаться завершения или явно отменить текущие проверки до обновления Strix.
- Сделать резервную копию БД Portico и БД управляющего API Strix по принятой процедуре.
- Разрешить приложению Portico два дополнительных OIDC redirect URI: `https://<portico-host>/admin/callback` и `https://<portico-host>/portal/callback`. Прежний `/oauth/callback` оставить.
- Создать административную группу, указанную в `config.admin.groups`, и назначить администратора. Пользовательскому порталу достаточно группы, разрешённой для сервиса Strix.
- Разрешить ключу LiteLLM требуемые модели. Сам ключ не изменяется.
- Действующие манифесты Secret хранить вне каталога, предназначенного для публикации. В репозитории находятся только образцы без значений.
- Рабочие значения Helm хранить в отдельном закрытом файле. `deploy/chart/values.yaml` содержит универсальные значения, а не настройки конкретного контура. При обновлении передать рабочий файл через `-f /path/to/private-values.yaml`.
- Проверить доступ models к БД Portico и core к каталогу LiteLLM. Миграция создаёт отдельные таблицы правил, аудита и входа; существующие пользовательские сессии не очищаются.

## Порядок

1. Обновить Strix до версии с новыми маршрутами отчётов, диагностикой и очередью.
2. Обновить Portico с соответствующими операциями сервиса Strix и новыми образами, передав закрытые значения через `-f`.
3. Открыть `/admin/`, изменить правило доступа и проверить список моделей у тестового пользователя.
4. Открыть `/portal/`, убедиться в доступности своей истории и отсутствии чужих проверок у обычного пользователя.
5. Выполнить предварительную проверку и один запрос статуса через чат. После запуска модель должна вернуть идентификатор и ссылку на карточку, а не непрерывно опрашивать состояние.

Карточка расположена в Portico и не является встроенным виджетом Open WebUI. Переход выполняется по ссылке; статус обновляется без вызова модели. При обрыве связи отображается повтор подключения, при завершении сессии предлагается повторный вход.

Рекомендации в описаниях инструментов уменьшают лишние вызовы, но не являются жёстким ограничителем поведения модели. Проверка прав и разрешённых целей выполняется сервером независимо от текста модели.

Обновление требует нового образа Portico. Для портала проверок требуется совместимый управляющий API с маршрутами статуса, истории и опубликованных артефактов. Portico сам не выполняет сканирование и не создаёт PDF: он выдаёт файлы, сформированные подключённым API. Перед применением указать digest образа в рабочем `deploy/values.yaml`; затем проверить административный интерфейс, портал и доступ обычного пользователя только к разрешённым проверкам.
