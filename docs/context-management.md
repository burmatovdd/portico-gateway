# Управление контекстом модели

Лимиты задаются отдельно для каждой модели в `models.config.context_budgets`:

```yaml
context_budgets:
  chat:
    window_tokens: 16384
    reserve_tokens: 2048
```

`window_tokens` должен соответствовать доступному контексту одного запроса на сервере модели. Это не обязательно общий объём, указанный серверу при нескольких параллельных слотах. `reserve_tokens` оставляет место для ответа. Если клиент уже передал больший допустимый лимит ответа, расчёт учитывает его.

Для текстовых сообщений шлюз оценивает объём запроса с учётом схем инструментов и удаляет старые завершённые пользовательские ходы при превышении планового бюджета. Системные инструкции, developer-сообщения, последний пользовательский ход и связанные с ним вызовы инструментов с результатами сохраняются. Это сокращение истории, а не смысловое резюме. Полная история в клиенте чата не изменяется.

Оценка по размеру JSON является эвристикой, а не результатом токенизации. Запрос, который нельзя безопасно сократить, передаётся серверу модели для окончательной проверки. При подтверждённом ответе HTTP 400 о переполнении допускаются не более двух повторов, каждый только после дополнительного удаления завершённых старых ходов. Принятые потоки ответов, транспортные ошибки и вызовы инструментов автоматически не повторяются.

Неподдерживаемые для безопасного сокращения форматы, включая мультимодальные сообщения и нарушенные связи tool-call/result, передаются без переписывания истории. При неизменяемом слишком большом запросе возвращается `context_length_exceeded` с понятным сообщением. Нельзя гарантировать продолжение любого задания: одни только обязательные инструкции или схемы инструментов могут превышать лимит.

В журнал записывается число удалённых ходов, без содержимого сообщений. Ответ содержит `X-Portico-Context-Turns-Removed`, когда история сокращена. Отображение этого заголовка зависит от клиента и само по себе не добавляет уведомление в Open WebUI.

Агенты Strix обращаются к LiteLLM отдельно от модельного шлюза Portico. Их автоматическое сжатие управляется настройками `context` Helm-чарта Strix; параметры шлюза не заменяют эти настройки. Согласованные лимиты необходимы на обоих маршрутах.

## Ошибки аргументов инструментов

Если провайдер возвращает корректный JSON с известным сообщением
`Failed to parse tool call arguments as JSON` и HTTP 400 либо 500, Portico
возвращает HTTP 502 с кодом `tool_arguments_invalid` и безопасным пояснением.
Исходные аргументы, адреса и текст провайдера в ответ не копируются. Ошибка
не считается переполнением контекста и не запускает его сокращение. Повторное
формирование аргументов выполняет агент, владеющий состоянием инструментов;
шлюз не должен повторять выполненные действия.

Заголовок `X-Portico-Context-Turns-Removed` позволяет интеграции клиента показать
отдельный статус сокращения истории. Обработка этого заголовка не меняет текст
ответа модели. Наличие заголовка не означает семантическую саммаризацию:
Portico исключает завершённые старые шаги из конкретного запроса, сохраняя
текущий запрос и системные инструкции.
