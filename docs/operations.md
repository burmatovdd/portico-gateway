# Эксплуатация и диагностика

## Проверка состояния

Для релиза `portico-gateway` в namespace `portico`:

```sh
kubectl -n portico get pods
kubectl -n portico logs deployment/portico-gateway-core --tail=50
kubectl -n portico logs deployment/portico-gateway-models --tail=50
```

Последняя команда применяется только при включённом models. Проверить DNS, HTTPS, HTTPRoute, доступность зависимостей и затем [пользовательский сценарий](verification.md).

## Типовые ошибки

| Симптом | Проверка |
| --- | --- |
| Модели отсутствуют | Подпись и audience JWT, groups, owner, правила models, эффективное подключение чата |
| Инструмент видит только администратор | Разрешения MCP-подключения на стороне чата |
| Casdoor снова требует пароль | Организация приложения и пользователя, cookie-сессия IdP и настройки автоматического входа |
| `passwordObfuscatorType` | Загрузка организации приложения в Casdoor; ошибка не равнозначна неверному паролю |
| `invalid_grant` | Этап обмена: одноразовый код, срок, повторное использование, redirect URI и PKCE; либо refresh |
| Ошибка на `/oauth/callback` Portico | Ответ IdP, обмен токенов, проверка ID/access token, сохранение сессии |
| Ошибка TLS | Доверенные CA и имя сервера; отдельно для HTTPS и PostgreSQL |
| Отказ downstream API | Audience, права на объект и конфигурация целевого API |

Не исправлять `invalid_grant` отключением PKCE или проверок токенов. Новую попытку начинать из клиента, а не обновлением callback. Для расследования нужны время, сервис, этап и безопасный код причины. Публичная страница ошибки намеренно не раскрывает детали IdP.

Диагностика зависит от версии образа. В версии 0.1.5 добавлены записи stage и reason для обмена токенов, nonce, привязки личности и обмена кода Portico. Старые образы их не содержат. Отсутствие ошибки в журнале не доказывает успех. Не включать HTTP debug с телами token endpoint.

## Обновление

1. Сохранить БД, ключ шифрования и конфигурацию в защищённом хранилище.
2. Проверить изменения исходников, конфигурации и схемы БД выбранной версии.
3. Собрать и опубликовать новый образ. Обновить tag и digest в values: непустой digest имеет приоритет.
4. Проверить Helm render, выполнить обновление и сценарии приёмки.

HTML, CSS и изображение встроены в бинарник. Их изменение требует нового образа. Изменение Secret не обновляет переменные окружения запущенных контейнеров: требуется управляемый перезапуск. Откат образа допускается только при совместимости со схемой БД и конфигурацией.

## Сессии и резервные копии

Core хранит общее состояние в PostgreSQL. `max_age_seconds` ограничивает полный срок сессии, `idle_seconds` — неактивность. Фоновый refresh не продлевает срок неактивности. `portico_logout` не отменяет задачи downstream API. Выход из чата, IdP и Portico не является единым logout.

БД и ключ шифрования сохраняются согласованно. Потеря ключа делает токены в БД недоступными. Восстановление старой БД может восстановить отозванные credentials; до открытия доступа нужна процедура завершения восстановленных сессий. Автоматической ротации ключа шифрования нет.

## Ограничения

Нет административного интерфейса сессий, глобального logout и полного аудита действий. Права в JWT действуют до его обновления или истечения. Защита публичных endpoints от массовых запросов также настраивается на инфраструктурном Gateway. Portico не заменяет ограничения нагрузки исполнителей задач.

Не сохранять Authorization, cookies, коды OAuth, параметры callback и тела token endpoint в журналах или tracing. Прокси и Gateway проверяются отдельно от логирования приложения.
