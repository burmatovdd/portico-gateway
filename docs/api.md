# Интерфейсы

## Core

| Путь | Назначение |
| --- | --- |
| `/` | Информационная главная страница; не создаёт сессию |
| `/.well-known/oauth-protected-resource/mcp` | Metadata защищённого ресурса |
| `/.well-known/oauth-authorization-server` | OAuth metadata Portico |
| `/oauth/authorize` | Authorization Code с PKCE S256 |
| `/oauth/login` | Подтверждение входа |
| `/oauth/callback` | Ответ корпоративного IdP |
| `/oauth/token` | Обмен одноразового кода или refresh token |
| `/oauth/revoke` | Отзыв credentials клиента |
| `/mcp` | Streamable HTTP; Bearer token Portico |
| `/healthz`, `/readyz` | Проверки процесса и готовности |
| `/admin/` | Необязательный интерфейс правил доступа групп к моделям |
| `/portal/` | Необязательный портал статуса и отчётов подключённого сервиса |

Клиенты регистрируются заранее. Scope — `mcp`, resource — точный `config.public_url` с `/mcp`. PKCE обязателен и для публичных, и для конфиденциальных клиентов. Refresh token привязан к клиенту и ротируется; повторное использование заменённого токена отзывает семейство.

Операции имеют имена `<service>__<operation>`. Реестр находится в `config.services`; образец — [config/example.yaml](../config/example.yaml). Список фильтруется по разрешениям, права проверяются повторно при вызове. Шлюз не предоставляет универсальную оболочку или произвольный HTTP proxy.

`portico_logout` завершает текущую сессию. Целевому API передаётся access token IdP, а не opaque token Portico. API обязан проверять audience и права на объекты.

## Models

| Метод и путь | Назначение |
| --- | --- |
| `GET /v1/models` | Разрешённые пользователю модели |
| `POST /v1/chat/completions` | Запрос к разрешённой модели, в том числе потоковый |
| `GET /healthz`, `GET /readyz` | Проверки процесса models |

Авторизация — Bearer JWT IdP. Эти endpoints обслуживает отдельный Service. Чарт может маршрутизировать `/v1` через общий внешний домен, но MCP-токен Portico для этих методов не подходит.

Ответ 401 означает отсутствие действительных credentials; 403 — запрет запрошенной модели. Пустой список моделей при действительном JWT возможен, если ни одна группа не сопоставлена политике. Readiness не является проверкой всех внешних API и пользовательских прав.
